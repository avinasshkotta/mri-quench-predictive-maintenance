# External validation — NASA C-MAPSS FD001

> Reproduce: `python scripts/validate_cmapss.py --download`
> Artifacts: `reports/external_validation.json`, `reports/figures/cmapss_*.png`

## Why this exists

The MRI study is synthetic: the authors generated the data, so a strong test
score alone is weak evidence that the *method* works. C-MAPSS FD001 is public,
real (simulator-generated by NASA, but not by us), run-to-failure turbofan data
with an official held-out test set. It is the standard external check for
predictive-maintenance pipelines.

**What this validates:** the decision framework — within-horizon labelling,
causal windowed features, engine-grouped splits, threshold selection under a
false-alert budget, and event-level lead-time evaluation.

**What this does not validate:** the MRI LSTM weights. Different sensors,
sampling rate and physics make transfer meaningless. A HistGBDT on the same
causal feature philosophy is used here, with a logistic baseline.

## Data

| | |
|---|---|
| Dataset | NASA C-MAPSS FD001 (Saxena & Goebel, 2008) |
| Train | 20,631 rows, 100 engines, run to failure |
| Test | 13,096 rows, 100 separate engines, truncated before failure |
| Truth | `RUL_FD001.txt` — RUL at each test engine's final observed cycle |
| Sensors | 21; 6 constant in FD001 (`s1,s5,s10,s16,s18,s19`) dropped → 15 used |
| Provenance | sha256 of all three files recorded in `external_validation.json` |

Files are downloaded on demand and git-ignored (`data/external/cmapss/`).

## Protocol

| Choice | Value | Rationale |
|---|---|---|
| Task | failure within **30 cycles** | maintenance-planning analogue of the MRI 96 h horizon |
| Warning deadline | **15 cycles** | half the horizon; chosen so ≥ 16 official test engines are fully evaluable despite truncation |
| Features | 60 = 15 sensors × (10-cycle mean, 10-cycle std, deviation from the first-5-cycle baseline, 10-cycle slope) | same causal, trailing-only philosophy as the MRI features |
| Excluded inputs | engine id, cycle index, RUL | identity and age must not leak the answer |
| Split | 80 train engines / 20 validation engines, **grouped by engine** | row-level splits leak near-duplicate cycles |
| Threshold | max in-time event recall subject to **≤ 0.6 false alerts/engine** (1.0 × 0.6 safety, the MRI policy) | chosen on validation only, then frozen |
| Test | NASA's 100 official test engines | never used for threshold selection |

## Results

Champion: HistGBDT (logistic regression shown as the baseline).

| Metric | HistGBDT | LogReg |
|---|---|---|
| Validation PR-AUC (20 held-out engines) | 0.962 | 0.952 |
| **Test PR-AUC (100 official engines)** | **0.892** | 0.864 |
| Test ROC-AUC | 0.997 | 0.995 |
| Event recall — detected at all (25 observable) | **84 % (21/25)** | 68 % (17/25) |
| Event recall — ≥ 15 cycles lead (16 evaluable) | **75 % (12/16)** | 50 % (8/16) |
| Median lead (clamped) | 28 cycles | 26 cycles |
| Lead range (clamped) | 21–30 cycles | 17–30 cycles |
| False alerts | 18 (0.18/engine) | 9 (0.09/engine) |

The champion beats the linear baseline on every ranking and event metric at a
false-alert rate well inside the budget.

## Why the denominators are 25 and 16, not 100

Test trajectories stop at arbitrary points. Two honest exclusions:

* **Right-censored (75 engines):** true RUL at truncation > 30 cycles, so the
  failure horizon starts *after* the observed data. Event recall is not
  measurable; any alert they raise is correctly counted as a false alert.
* **Deadline already passed (9 of the 25 observable engines):** RUL at
  truncation < 15 cycles, so even a perfect model cannot warn 15 cycles ahead.
  They stay in "detected at all" but are excluded from the in-time denominator.

This is a property of C-MAPSS, not a modelling choice; hiding it would inflate
the headline.

## Interpretation

* **The methodology transfers.** A simple, causal, engine-grouped pipeline
  reaches PR-AUC 0.892 and 75 % in-time event recall on real turbofan data —
  with zero test-set tuning.
* **The generalisation gap is real.** Validation PR-AUC 0.962 → test 0.892,
  and in-time recall 100 % → 75 %. Truncation points and engine-to-engine
  variability differ between the splits; a production system needs
  site-specific calibration.
* **No dollar claim.** C-MAPSS has no maintenance costs, so the MRI $452k cost
  model is deliberately not applied. Inventing costs would be dishonest.
* **Not a model-transfer claim.** The MRI LSTM is unchanged and unvalidated on
  turbofans; only the decision framework is.

## Limitations

1. FD001 is the easiest subset (one operating condition, one fault mode);
   FD002–FD004 would test robustness to multiple conditions/faults.
2. Only 25 test engines have an observable event and 16 are evaluable in time —
   confidence intervals are wide.
3. The 30-cycle horizon is a design analogy, not an aviation-certified limit.
4. A single grouped split for threshold selection; nested cross-validation over
   engines would give a more stable operating point.
